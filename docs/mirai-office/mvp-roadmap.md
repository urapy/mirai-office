### 1. 画面移植スパイク

目的は、製品全体を作ることではなく「オフィス画面だけを子どもNISA用データで動かせるか」を確認すること。

1. 公式の開発手順で未変更版を起動する。
2. `webview-ui`、Canvas描画、経路探索、キャラクター状態の依存関係を調べる。
3. Claude/Codexイベントを使わず、固定JSONから3人を表示する。
4. 固定イベントで天気とキャラクターの行動を変える。
5. 必要なコードと削除可能なコードを一覧化する。

完了条件: 仮想投資イベントだけで、3キャラクター、天気、成長表現を再現できる。ここで「フォークを継続」か「画面部分だけ移植」かを最終決定する。

状態: 進行中。未変更版のビルドと643テスト、`127.0.0.1:3100`でのHTTP配信を確認済み。描画・状態機械・経路探索の依存関係を整理し、Vite開発モードではClaude/Codexイベントを使わず固定JSONから3人を投入できる。変更後のWebviewは88テスト成功。目視確認と、天気・成長表現の固定イベント接続が残っている。

### 2. 仮想商品の価格シナリオを実装する

MVPは乱数だけにせず、説明しやすく再現可能な30日固定シナリオを先に作る。

確定した3シナリオ:

| シナリオ     | 目的             | 30日間のイメージ             |
| ------------ | ---------------- | ---------------------------- |
| でこぼこ成長 | 基本デモ         | 上下しながら最終的に約5%上昇 |
| 雨のち晴れ   | 下落時の学習     | 中盤で約10%下落し、少し回復  |
| 長いくもり   | 利益保証を避ける | 横ばいと小幅下落で終了       |

各シナリオは同じ初期価格10,000、毎月の積立10,000円から始める。価格列は固定JSONで管理し、天気は前日比ではなく数日移動平均と変動幅から決める。損益とキャラクターの幸福度を結び付けない。

完了条件: 同じ入力で同じ結果になり、積立・評価額・損益の計算を単体テストできる。

状態: 進行中。3本×30日の固定JSON、初回積立に対する評価額・損益、5日窓の天気判定を実装し単体テスト済み。積立頻度、複数回買付、平均取得価格、履歴の計算は未実装。

### 3. 画面設計

画面を先に増やさず、次の2画面と1つの切替導線に絞る。

- 子どもホーム: オフィス、天気、今日の一言、目標の成長
- 保護者ダッシュボード: 元本、評価額、損益、積立設定、履歴、シナリオ操作
- 保護者導線: 子どもが誤って管理操作へ入らないための明確な切替

低精細ワイヤーフレーム → クリック可能な静的画面 → 実データ接続の順で進める。各段階で8〜12歳向けの言葉と、保護者向け数値の正確さを確認する。

完了条件: 主要タスク、表示情報、空・下落・エラー状態が画面単位で定義されている。

### 4. 技術設計

画面移植スパイクの結果を受けて、次を決める。

- React/Vite/Canvasをどこまで継承するか
- 仮想口座のドメインモデルと投資イベント
- UI状態と金融計算の境界
- ローカル保存方式
- `127.0.0.1` のみで動かす起動方式
- テスト戦略とアクセシビリティ
- Pixel Agents由来ファイルと独自ファイルの境界

完了条件: コンポーネント図、イベントフロー、データモデル、テスト範囲、ライセンス台帳がそろう。

### 5. 縦切りMVPを実装する

最初の縦切りは「保護者が1回積み立てる → 子ども画面に仲間が増える → 日付を進める → 天気と評価額が変わる」とする。その後、履歴、目標、学習カードを追加する。
